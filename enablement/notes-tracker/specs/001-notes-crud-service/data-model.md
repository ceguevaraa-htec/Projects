# Data Model: Personal Notes Tracking Service

## Note

Represents a single piece of personal information a user has captured (spec Key Entities).

| Field        | Type                | Required | Notes |
|--------------|----------------------|----------|-------|
| `id`         | `string`             | yes (system-assigned) | Unique identifier, assigned on create (e.g. UUID). Immutable after creation. |
| `title`      | `string`             | yes      | Must be non-empty (after trimming) per FR-002. |
| `content`    | `string`             | yes      | Must be non-empty (after trimming) per FR-002. |
| `updatedAt`  | `string` (ISO 8601)  | yes (system-assigned) | Set on create; reset to the current time on every successful update, per FR-007. |

### Validation rules

- `title` and `content` MUST both be present and non-empty (after trimming whitespace) to
  create a note (FR-002). The same rule applies to any value supplied on update — a supplied
  `title` or `content` that is empty/whitespace-only is rejected; a field simply omitted from an
  update request is left unchanged (spec Assumptions: partial update).
- An update request MUST supply at least one of `title`/`content`; a request supplying neither
  is rejected (FR-010).
- `id` is generated by the repository layer on create and is never accepted as client input.
- `updatedAt` is never accepted as client input; it is always computed by the service layer at
  the moment of a successful create or update (FR-007).

### State transitions

- **Created**: note comes into existence with a `title`, `content`, system-assigned `id`, and
  `updatedAt` set to the creation time.
- **Updated**: `title` and/or `content` change; `updatedAt` is reset to the time of that change.
  An update supplying the same values the note already has is a valid, successful update
  (idempotent per spec Assumptions) and still refreshes `updatedAt`.
- **Deleted**: note is removed entirely; no soft-delete/tombstone state — after deletion the
  note's `id` no longer resolves to anything (FR-008).

### Relationships

None. Notes are flat, independent records (spec Assumptions) — no folders, tags, categories, or
references between notes.
